# Гибридная СППР: ЦИКЛ + LLM для разметки чувствительных данных

Реализация дипломной работы «Интеграция больших языковых моделей в систему
поддержки принятия решений для разметки чувствительных данных».

Система классифицирует столбцы банковского хранилища данных по четырём
уровням конфиденциальности (C₁–C₄), интегрируя метод многокритериальной
классификации **ЦИКЛ** с большой языковой моделью.

## Архитектура

Двухфазная гибридная система с принципиальным разделением ролей LLM:

**Фаза 1 (offline, один раз) — построение решающего правила.**
LLM выступает в роли **ЛПР**: получает гипотетический вектор оценок (K₁–K₆)
и относит его к одному из 4 классов. Метод ЦИКЛ опрашивает LLM на
специально подобранных векторах и через процедуры S (распространение по
доминированию), D (бинарный поиск) и R (устранение противоречий) строит
полную lookup-таблицу на все 1296 векторов. Результат сохраняется в
`rules/rule_<provider>_<model>.json`.

**Фаза 2 (online) — оперативная классификация.**
LLM выступает в роли **оценщика**: получает 4 атрибута реального столбца
(название таблицы, описание таблицы, название поля, описание поля) и
возвращает вектор оценок K₁–K₆ + текстовое обоснование. Класс определяется
детерминированно через lookup в таблице из Фазы 1 — LLM не выносит
итоговое решение напрямую.

## Система критериев

6 критериев, 4 класса конфиденциальности, |Y| = 4×3×3×4×3×3 = **1296** векторов.

| Критерий | Градации |
|---|---|
| К₁ — степень нормативного регулирования | 4 |
| К₂ — совокупный ущерб для организации | 3 |
| К₃ — прямая криминальная ценность | 3 |
| К₄ — воздействие на субъект данных | 4 |
| К₅ — критичность для бизнес-процессов | 3 |
| К₆ — джойнабельность / квази-идентификатор потенциал | 3 |

**Классы:** C₁ Строго конфиденциально → C₂ Конфиденциально →
C₃ Для внутреннего использования → C₄ Общедоступно

## Структура

```
diploma_dss/
├── dss/
│   ├── criteria.py          — 6 критериев и 4 класса (единственный источник данных)
│   ├── tsikl.py             — ядро метода ЦИКЛ (процедуры S, D, R)
│   ├── llm_client.py        — клиенты Anthropic / OpenAI / DeepSeek / Manual
│   ├── decision_maker.py    — Фаза 1: LLM как ЛПР
│   ├── assessor.py          — Фаза 2: LLM как оценщик
│   ├── decision_rule.py     — lookup-таблица, save/load/verify
│   ├── expert_guidance.py   — методологические блоки для промптов
│   └── pipeline.py          — build_decision_rule / classify_column / classify_batch
├── build_rule.py            — CLI Фазы 1
├── classify.py              — CLI Фазы 2 (одиночный + batch-режим)
├── check_rule.py            — проверка полноты правила (все 1296 векторов)
├── app.py                   — Streamlit веб-интерфейс
├── rules/                   — решающие правила (rule_<provider>_<model>.json)
├── results/                 — результаты классификации (авто-именование)
└── requirements.txt
```

`criteria.py` — единственный источник данных о критериях и классах.
Промпты собираются автоматически из него и `expert_guidance.py`.

## Установка

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# Установить один или несколько API-ключей:
$env:ANTHROPIC_API_KEY="sk-ant-..."
$env:OPENAI_API_KEY="sk-..."
$env:DEEPSEEK_API_KEY="sk-..."
```

## Использование

### Фаза 1. Построение решающего правила

```powershell
py build_rule.py --provider anthropic
py build_rule.py --provider anthropic --model claude-sonnet-4-6
py build_rule.py --provider openai --model gpt-4o
py build_rule.py --provider deepseek
```

Правило сохраняется в `rules/rule_<provider>_<model>.json`.

### Проверка полноты правила (обязательно перед Фазой 2)

```powershell
py check_rule.py --rule rules/rule_anthropic_claude-sonnet-4-6.json
```

### Фаза 2. Оперативная классификация

Один столбец через аргументы:
```powershell
py classify.py --rule rules/rule_anthropic_claude-sonnet-4-6.json --provider anthropic --model claude-sonnet-4-6 --field client_inn_fl --description "ИНН клиента — физического лица"
```

Пакетная обработка из CSV:
```powershell
py classify.py --rule rules/rule_anthropic_claude-sonnet-4-6.json --provider anthropic --model claude-sonnet-4-6 --input test_columns_440_clean.csv
```

Результаты сохраняются в `results/results_<provider>_<dataset>.csv`.

### Веб-интерфейс

```powershell
py -m streamlit run app.py
```

## Технические особенности реализации

**ЦИКЛ.** Раннее прекращение процедуры D при разрыве классов = 1: граница уже
локализована, дальнейшее углубление не даёт нового знания. Неоднозначные
векторы достраиваются через `⌊(C^L + C^U) / 2⌋` без обращения к ЛПР —
округление к меньшему номеру класса соответствует более чувствительному
классу (принцип осторожности). На практике опрашивается 4–7% от |Y|
(50–90 запросов из 1296).

**Метаданные правила** (`rule.json`) включают: провайдер и модель, дату
построения, число обращений к ЛПР, время построения, счётчики
противоречий, итераций процедуры R, зажатий и ошибок парсинга.

**Надёжность.** Все провайдеры используют retry с экспоненциальным backoff
(2→4→8 сек) на 429/5xx/сетевые ошибки, timeout=60 сек. Prompt caching
включён для Anthropic (~90% скидка на повторные запросы системного промпта).

**Оценщик.** `_extract_json` берёт последний валидный JSON-блок в ответе —
защита от «рассуждений вслух» с промежуточными JSON-фрагментами.
CSV читается с `encoding="utf-8-sig"` для корректной обработки BOM.
